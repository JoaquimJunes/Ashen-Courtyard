# ADR 002 — deterministic world data and explicit persistence

**Accepted direction: 20 September 2026. Implementation deferred.**

A seamless procedural world must not change because regions load in a different
order or the game updates. Use independently derived random streams and versioned
world manifests, placing required landmarks before optional structures. Store
persistent entity changes by stable IDs, independently from node paths and default
generated data. Preserve dungeon layouts and landmark placements in saves.

Structural damage persists as broken connections and physical-piece state; it is
not regenerated by replaying a collapse. Version saves and use temporary writes
plus a previous valid backup. Validate a safe position against loaded collision
before resuming. Ordinary enemies reset at checkpoints; major changes remain.

The only current implementation is `PersistentEntityState`, a copied record
contract. Generation, streaming, saving, equipment and checkpoint progression are
not claimed as implemented by this decision.

References: [Godot RNG caveat](https://docs.godotengine.org/en/4.6/classes/class_randomnumbergenerator.html),
[thread-safety guidance](https://docs.godotengine.org/en/4.6/tutorials/performance/thread_safe_apis.html).
